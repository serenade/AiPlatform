# AIR 平台复刻蓝图

> 对应分析报告：`01-平台架构分析报告.md`
> 目标：复刻 platform.fullstack-dao.com 的核心体验——"AppSpec-first 的 AI 对话式应用搭建平台"
> LLM 策略（已确认）：**OpenAI 兼容 API 优先（BASE_URL + API_KEY + MODEL 可配），未配置时自动降级 Mock 模式**，保证零依赖演示

---

## 1. 目标与非目标

**目标（MVP 全部覆盖）**
1. 邮箱密码登录 + Session 会话（贴近原版 `air_session`/`air_csrf` 机制）
2. 多租户数据模型（tenant → apps → AppSpec 版本）
3. 应用列表页 + 新建应用
4. Builder 对话页：ChatKit SSE 流式对话，Agent 生成/修改 AppSpec，产出 SpecPatch 提案，用户确认后 apply
5. AppSpec v0.3（简化子集）版本化存储与 JSON 预览
6. Agent Server 健康检查、threads 搜索/置顶、后台 Run 骨架
7. OpenAI 兼容 + Mock 双模式，运行时自动探测

**非目标（后续迭代）**
- 应用壳独立域名（apps.xxx.com）与已发布应用的真实运行时
- 实时浏览器帧（browser-frame）、语音输入、附件上传
- 自动化 workflows、集成 integrations 的执行引擎
- 团队成员管理、审计事件、product-memory 完整实现（预留表结构与端点桩）

## 2. 技术选型（贴近原架构）

| 层 | 选型 | 理由 |
|---|---|---|
| Monorepo | pnpm workspace + 少量 Python 目录 | 前后端同仓，贴近原版三服务形态 |
| 前端 | Next.js 15 (App Router) + Tailwind CSS + `@openai/chatkit-react` | 与原版一致；ChatKit 官方 React 绑定 |
| 平台 API | Node 20 + Express 4 + better-sqlite3 + zod | 复刻 `X-Powered-By: Express`、`RuntimeRequestError` 错误体 |
| Agent Server | Python 3.11 + FastAPI + `openai-chatkit` + OpenAI SDK | 复刻 ChatKit 单端点 SSE；SDK 为 Apache-2.0 官方开源 |
| 存储 | SQLite 单文件（api 与 agent-server 各自独立库） | 零运维，docker volume 挂载即持久化 |
| 部署 | docker-compose（web / api / agent-server 三容器） | 一键启动 |

LLM 接入统一约定（Agent Server 环境变量）：

```bash
# 三者齐全 → 真实模式；任一缺失 → Mock 模式
LLM_BASE_URL=https://api.deepseek.com/v1   # 任意 OpenAI 兼容端点
LLM_API_KEY=sk-xxx
LLM_MODEL=deepseek-chat
LLM_MOCK=auto        # auto(默认，无key自动mock) | on | off
```

## 4. 数据库设计（SQLite）

```sql
-- api/data/platform.db
CREATE TABLE users (
  id TEXT PRIMARY KEY,            -- user_<uuid>
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,    -- scrypt/pbkdf2
  display_name TEXT, avatar_url TEXT,
  created_at TEXT NOT NULL
);
CREATE TABLE tenants (
  id TEXT PRIMARY KEY,            -- tenant_<uuid>
  name TEXT NOT NULL, slug TEXT UNIQUE NOT NULL, avatar_url TEXT
);
CREATE TABLE memberships (
  user_id TEXT REFERENCES users(id),
  tenant_id TEXT REFERENCES tenants(id),
  role TEXT NOT NULL,             -- admin | member
  status TEXT NOT NULL,           -- active
  is_current INTEGER DEFAULT 1,
  PRIMARY KEY (user_id, tenant_id)
);
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,            -- 随机 token，即 air_session 值
  user_id TEXT NOT NULL, tenant_id TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
CREATE TABLE apps (
  id TEXT PRIMARY KEY,            -- app_<uuid> 或用户自定义 slug
  tenant_id TEXT NOT NULL,
  name TEXT NOT NULL, description TEXT, icon_asset_id TEXT,
  status TEXT NOT NULL DEFAULT 'draft',          -- draft | active
  current_draft_spec_version_id TEXT,
  current_published_spec_version_id TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE spec_versions (
  id TEXT PRIMARY KEY,            -- specver_<uuid>
  app_id TEXT NOT NULL REFERENCES apps(id),
  version INTEGER NOT NULL,
  spec_json TEXT NOT NULL,        -- 完整 AppSpec
  created_by TEXT NOT NULL, created_at TEXT NOT NULL,
  source TEXT NOT NULL            -- manual | agent_patch
);
```

agent-server 的 `agent.db`：`threads`、`thread_items`、`runs`、`proposals`（由 openai-chatkit store 接口适配，含 `pinned`、`visibility`、`metadata` 字段以支持重启后 proposal 回退）。

## 5. 平台 API 契约（复刻对齐版）

通用约定：
- 所有响应头带 `X-Request-Id: req_<uuid>`；错误统一 `RuntimeRequestError` 结构（code: `INVALID_REQUEST` / `AUTHENTICATION_REQUIRED` / `FORBIDDEN` / `NOT_FOUND`）。
- 会话 cookie：`air_session`（HttpOnly/Secure/SameSite=Lax/14d）+ `air_csrf`；写操作校验 `x-csrf-token` 头。

| 端点 | 请求 | 响应 |
|---|---|---|
| `POST /api/auth/login` | `{email, password}` | `{user, tenant, membership, tenants[], authContext}` + Set-Cookie |
| `POST /api/auth/logout` | — | 204 |
| `GET /api/auth/me` | — | 同 login 响应体 |
| `GET /api/tenants` | — | `{tenants[]}` |
| `GET /api/apps` | — | `App[]`（结构与原版一致，见报告 §6） |
| `POST /api/apps` | `{name, description?}` | 创建 app + 初始空 AppSpec v0.3 草稿版本 |
| `GET /api/apps/:id` | — | `App` |
| `PATCH /api/apps/:id` | `{name?, description?, status?}` | `App` |
| `DELETE /api/apps/:id` | — | 204 |
| `GET /api/apps/:id/spec` | `?version=` | `{specVersion, ...spec}`（默认当前草稿） |
| `PUT /api/apps/:id/spec` | 完整 spec | 新建草稿版本（版本号自增） |
| `POST /api/apps/:id/publish` | — | 把 `current_draft_spec_version_id` 复制为 published 指针，`status=active` |
| `GET /api/apps/:id/spec-versions` | — | 版本历史列表 |
| `GET /api/apps/:id/workspace` / `environments` | — | MVP 返回桩数据（对齐原版路径） |

login 响应示例（与实测原版同构）：

```json
{
  "user": {"id":"user_...","email":"admin@test.com","displayName":"管理员","avatarUrl":null},
  "tenant": {"id":"tenant_...","name":"默认租户","slug":"default","avatarUrl":null},
  "membership": {"role":"admin","status":"active"},
  "tenants": [{"id":"tenant_...","name":"默认租户","slug":"default","avatarUrl":null,"role":"admin","status":"active","isCurrent":true}],
  "authContext": {"actorId":"user_...","tenantId":"tenant_...","roles":["admin"],"subjectType":"platform_user"}
}
```

## 6. Agent Server 设计（核心）

### 6.1 ChatKit 服务骨架

```python
# agent-server/app/server.py
from chatkit.server import ChatKitServer
from chatkit.agents import stream_agent_response   # SDK 提供的 agent 流式适配

class AirChatKitServer(ChatKitServer):
    def __init__(self, store: AirStore, llm: LlmClient, spec_service: SpecService):
        super().__init__(store, context_factory=...)
        self.llm, self.spec_service = llm, spec_service

    async def respond(self, thread, item_input, context):
        # 1) 取应用当前 AppSpec（context 携带 app_id）
        spec = await self.spec_service.current_spec(context.app_id)
        # 2) 构造系统提示词：AppSpec 现状 + SpecPatch JSON Schema + 输出约定
        # 3) 调 LLM（真实或 Mock），流式产出：
        #    - 文本解释（assistant 消息，SSE 推给前端）
        #    - <spec_patch> JSON 块（解析缓存，不进协议）
        # 4) 流结束后把 SpecPatch 存入 thread.metadata + proposals 表
        ...
```

关键决策（对齐原版行为）：
- **单端点 `/chatkit`**：POST，流式操作返回 `StreamingResponse(text/event-stream)`，非流式返回 JSON —— 与 openai-chatkit 官方 FastAPI 接法一致，也与原版 OpenAPI 描述一字不差。
- **SpecPatch 不走 ChatKit 事件协议**：流结束后前端单独 `GET /chatkit/threads/{id}/proposal` 拉取 —— 与原版 OpenAPI 中 proposal 端点的描述完全一致。
- **`POST /chatkit/apply`**：`{app_id, thread_id}` → 校验 proposal → 调平台 API `PUT /api/apps/:id/spec` 落新版本 → 返回新 specVersion。
- **`POST /internal/mcp/discover`**：MVP 返回桩（校验 URL 可达 + 返回空工具列表），接口形状与原版一致。
- **后台 Run 族端点**（`/chatkit/runs*`）：MVP 建表 + 基本生命周期（202 创建、snapshot/events/cancel/resolve 状态机），由 Mock/真实 LLM 同步完成后即结束，端点形状对齐原版。

### 6.2 SpecPatch 格式（自定义，蓝图定义）

Agent 输出约定（嵌在回复末尾的代码块中）：

```json
{
  "type": "spec_patch",
  "summary": "新增了会议室预订模型和列表页面",
  "operations": [
    {"op": "add_model",    "model": {"id":"meeting_room","name":"会议室","fields":[...]}},
    {"op": "update_model", "modelId":"meeting_room", "fields":[...]},
    {"op": "remove_model", "modelId":"meeting_room"},
    {"op": "add_seed",     "modelId":"meeting_room", "rows":[...]},
    {"op": "add_page",     "page": {"id":"rooms_page","title":"会议室列表","type":"table","modelId":"meeting_room"}},
    {"op": "set_navigation","items":[{"id":"nav_rooms","label":"会议室","pageId":"rooms_page"}]},
    {"op": "set_metadata", "key":"shell.mode", "value":"workspace"}
  ]
}
```

服务端逐条校验（模型 id 唯一、relation targetModelId 存在、page 引用的 modelId 存在等），非法 op 拒绝并在 proposal 上标 `errors`。

### 6.3 LLM 双模式

```
启动时探测：LLM_MOCK=on → Mock
           LLM_MOCK=off 且缺配置 → 启动报错
           auto（默认）→ 有 BASE_URL+KEY+MODEL 用真实，否则 Mock
```

- **真实模式**：OpenAI SDK `base_url=LLM_BASE_URL`，流式 chat.completions；系统提示词含当前 AppSpec JSON + SpecPatch schema + few-shot 一个完整示例。
- **Mock 模式**：`llm/mock.py` 提供确定性剧本——按用户输入关键词匹配（如含"预订/会议"→ 返回会议室预订 SpecPatch；含"客户"→ CRM 雏形；默认 → 通用"任务管理"应用骨架），以 200–400ms 间隔流式吐出文本，最后吐 SpecPatch 块。保证**无任何外部依赖时全流程可演示**（对话 → 提案 → apply → spec 变更可见）。
- Mock 与真实模式输出同一 SpecPatch 协议，上层无感知。

### 6.4 对话上下文注入

ChatKit context 携带：`{app_id, tenant_id, user_id}`（前端通过自定义 header/first user message metadata 传入，服务端校验会话归属）。系统提示词拼入：
1. 平台定位说明（"你是 AppSpec 应用搭建助手"）
2. 当前 AppSpec 全量 JSON
3. SpecPatch schema + 规则（只输出增量操作，不重复全量）
4. 产品记忆摘要（MVP 为 app.description）

## 7. 前端设计

| 页面 | 路由 | 要点 |
|---|---|---|
| 登录 | `/auth/login` | 邮箱+密码，POST /api/auth/login，成功跳 /apps |
| 应用列表 | `/apps` | 卡片网格（icon、名称、描述、draft/active 徽标、更新时间），"新建应用"按钮 + 名称弹窗 |
| Builder | `/apps/[appId]/builder` | 左侧模块导航（应用工作台/数据库/集成/自动化/发布中心/用户与权限/应用配置），中央为对应面板，右侧为 ChatKit 对话栏 |
| 设置 | `/settings` | 模型配置（展示 agent-server 的 LLM 模式与当前 model 名）、Skills/MCP/智能能力 桩页 |

Builder 对话栏核心代码形态（官方用法）：

```tsx
'use client';
import { ChatKit, useChatKit } from '@openai/chatkit-react';

export function BuilderChat({ appId }: { appId: string }) {
  const { control } = useChatKit({
    api: { url: `${AGENT_SERVER_URL}/chatkit`, domainKey: 'local-dev' },
    // 附加头：app 归属上下文
  });
  return <ChatKit control={control} className="h-full" />;

```

SpecPatch 确认流：轮询/流结束后调用 `GET /agent/chatkit/threads/{id}/proposal` → 渲染操作清单 diff 卡片（新增模型/字段/页面分组展示）→ "应用更改"按钮调 `POST /agent/chatkit/apply` → 成功后刷新右侧 AppSpec 面板（`GET /api/apps/:id/spec`）。

主题：中文界面，品牌名占位"智联无界"可换成自定品牌；布局贴近原版截图（浅色、左侧窄边栏、内容卡片化）。

## 8. 部署（docker-compose）

```yaml
services:
  api:
    build: apps/api
    environment: [PORT=4000, DB_PATH=/data/platform.db, SEED_ADMIN_EMAIL=..., SEED_ADMIN_PASSWORD=...]
    volumes: [api-data:/data]
    ports: ["4000:4000"]
  agent-server:
    build: agent-server

      - LLM_BASE_URL=${LLM_BASE_URL:-}
      - LLM_API_KEY=${LLM_API_KEY:-}
      - LLM_MODEL=${LLM_MODEL:-}
      - LLM_MOCK=${LLM_MOCK:-auto}
      - PLATFORM_API_URL=http://api:4000/api
    volumes: [agent-data:/app/data]
    ports: ["8100:8100"]
  web:
    build: apps/web
    environment:
      - NEXT_PUBLIC_PLATFORM_API_URL=/api
      - NEXT_PUBLIC_AGENT_SERVER_URL=/agent
    ports: ["3000:3000"]
    depends_on: [api, agent-server]

```

MVP 阶段 web 用 Next.js rewrites 把 `/api/*`、`/agent/*` 反代到两容器，避免 CORS，等价原版同域代理形态。

## 10. 风险与开放问题

1. **`@openai/chatkit-react` 需要加载 ChatKit.js 远端脚本**（官方 web component 从 CDN 加载）——若部署环境无外网，需自托管 chatkit-js 产物或降级为自研 SSE 聊天组件（协议层不变，仅换 UI 皮）。
2. **SpecPatch 质量依赖提示词**：真实模式下模型可能输出非法 op；靠服务端校验 + 单轮重试（resolve: retry 语义）兜底。
3. **会话打通**：原版 agent-server 复用 `air_session` cookie 鉴权（`Missing session cookie`）。复刻版 MVP 用同一 SQLite 库或共享 session 密钥校验，蓝图按"api 签发、agent-server 本地校验"设计。
4. **AppSpec 完整性**：原版 specVersion 0.3 共 15 个顶层键，MVP 只实现 models/seeds/pages/actions/navigation/shell/policy 七个，其余键位预留透传不解析——保证向后兼容升级。
5. **发布的应用运行时**（app shell 渲染 AppSpec）是原版最重的部分，已列为非目标；若后续需要，可做一个极简 table+form 渲染器先跑通"发布→预览"。
