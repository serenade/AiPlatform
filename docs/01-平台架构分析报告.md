# platform.fullstack-dao.com 架构分析报告

> 侦察日期：2026-10-20　|　目标：判定平台技术来源（Pi Agent / DeepSeek DSH / 其他开源）
> 结论先行：**平台主体为自研，非 Pi、非 DSH；唯一重度依赖的开源组件是 OpenAI ChatKit 协议（前后端 SDK 均为 Apache-2.0 开源）**

---

## 1. 平台概况

| 项目 | 内容 |
|---|---|
| 对外品牌 | 智联无界·企业应用平台（logo：`zennect_logo.ico`，品牌 Zennect） |
| 平台定位 | "面向 AppSpec-first 生成应用的 AI Builder 工作台"（meta description 原文） |
| 内部代号 | **AIR**（cookie `air_session`/`air_csrf`，全局配置 `window.__AIR_AGENT_CONFIG__`） |
| 入口 | `https://platform.fullstack-dao.com/auth/login`（邮箱+密码，无验证码/SSO） |
| 应用壳 | `https://apps.fullstack-dao.com`（独立域名，承载发布后的应用） |

## 2. 总体架构（实测证据还原）

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器                                                      │
│   ├─ platform.fullstack-dao.com      （Next.js 前端）        │
│   └─ apps.fullstack-dao.com          （已发布应用 App Shell） │
└──────────────┬──────────────────────────┬───────────────────┘
               │ /api/*                   │ /agent/*
               ▼                          ▼
┌──────────────────────────┐   ┌──────────────────────────────┐
│  平台 API（Express/Node） │   │  Agent Server（FastAPI/Python）│
│  · auth/session 登录      │   │  · ChatKit 协议单端点 /chatkit │
│  · tenants 多租户         │   │  · SSE 流式 / 后台 Run        │
│  · apps + AppSpec 版本库  │   │  · SpecPatch 提案 / apply     │
│  · product-memory/审计    │   │  · 附件 / MCP 发现 / 浏览器帧  │
└──────────────────────────┘   └──────────────────────────────┘
```

三服务地址由前端 `runtime-config.js` 统一注入：

```js
window.__AIR_AGENT_CONFIG__ = {
  "platformApiUrl": "https://platform.fullstack-dao.com/api",
  "agentServerUrl": "https://platform.fullstack-dao.com/agent",
  "appShellUrl": "https://apps.fullstack-dao.com"
};
```

## 3. 各层技术指纹与证据

### 3.1 前端 — Next.js（App Router）
- 页面含 `__next_s` / `__next_f` hydration 标记，静态资源走 `_next/static/chunks/`；无 `__NEXT_DATA__`（排除 Pages Router），无 vite/nuxt/ng 特征。
- 全部前端路由（实测确认）：

| 路由 | 页面 |
|---|---|
| `/auth/login` | 登录 |
| `/apps` | 应用列表（全局侧边栏：应用列表、团队、Skills、MCP、智能能力、模型配置） |
| `/apps/[appId]/builder` | Builder·应用工作台 |
| `/apps/[appId]/data` | 数据库（Data Browser） |
| `/apps/[appId]/integrations` | 集成 |
| `/apps/[appId]/automations` | 自动化 |
| `/apps/[appId]/releases` | 发布中心 |
| `/apps/[appId]/access` | 用户与权限 |
| `/apps/[appId]/settings` | 应用配置 |
| `/settings/team?tab=members` | 团队设置（团队信息/成员/组织架构/邀请/企业微信/微信小程序 六个内部子 Tab） |
| `/settings/team?tab=skills` | 团队 Skills |
| `/settings/team?tab=mcp` | 团队 MCP |
| `/settings/team?tab=capabilities` | 智能能力（AI Profile） |
| `/settings/team?tab=ai-profiles` | 模型配置（Agent Profile） |

- Builder 对话输入区：文本框 + 图片上传 + Skills 按钮 + 语音输入 + 发送；右侧含历史会话区与预览面板。

### 3.2 平台 API — Express (Node.js)
- 响应头 `X-Powered-By: Express`、`ETag: W/"..."`、`X-Request-Id: req_<uuid>`。
- 统一错误体（自定义 `RuntimeRequestError`）：

```json
{"error":"RuntimeRequestError","code":"INVALID_REQUEST","statusCode":400,
 "requestId":"req_09e5bebb-...","timestamp":"2026-10-20T11:25:32.459Z",
 "path":"/auth/login","message":"..."}
```

- 会话机制：服务端 Session Cookie，非 JWT。
  - `air_session`：HttpOnly + Secure + SameSite=Lax，有效期 14 天
  - `air_csrf`：非 HttpOnly，供前端携带 CSRF

### 3.3 Agent Server — FastAPI (Python)
- `/agent/openapi.json` 完全公开（OpenAPI 3.1），`info.title = "智联无界·企业应用平台 Agent Server"`，`version 0.1.0`。
- 鉴权失败返回 FastAPI 风格体：`{"detail":"Missing session cookie"}`（与 Express 错误体风格截然不同 → 独立 Python 服务实锤）。
- 健康检查：`GET /agent/health` → `{"ok":true,"service":"agent-server"}`。

## 4. 全站功能清单（2026-10-20 完整遍历）

> 遍历方式：浏览器自动化走查 + SSR HTML/RSC 载荷提取，覆盖全部 14 个路由。
> 未尽事项（低风险）：应用工作台页为纯客户端渲染仅确认骨架；组织架构/企业微信/微信小程序三个子 Tab 的字段级细节、用户头像菜单项未逐字确认。

### 4.1 应用列表 `/apps`
- 应用卡片：图标、状态标签（draft/active）、名称、描述、创建日期；无搜索/筛选/排序控件。
- 「新建应用」弹窗：应用名称 + 简介，创建后直接跳入 builder。

### 4.2 Builder·应用工作台 `/apps/[id]/builder`
- 布局：左侧应用模块导航（7 项）+ 中央工作区 + 右侧历史会话区与预览面板。
- AI 对话栏：文本输入、图片上传、Skills 选择、语音输入、发送。
- 顶栏环境徽标：Development（当前环境标识）。

### 4.3 数据库 `/apps/[id]/data`
- Data Browser：数据表列表（N 个定义、每表 N 条记录）、添加记录、导入、同步 Seed。
- 环境 Tab：开发 / 生产；空态文案"没有可访问的数据表"。

### 4.4 集成 `/apps/[id]/integrations`
- "外部能力与环境连接"：添加集成、N 个环境已就绪、导入记录。

### 4.5 自动化 `/apps/[id]/automations`
- 流程与运行：流程列表（N 个流程）、自动化定义、运行记录。
- 触发方式筛选：全部 / Webhook / 定时 / 数据事件；状态含"尚未发布"。

### 4.6 发布中心 `/apps/[id]/releases`
- 当前环境、发布流程（开发环境 → 生产环境）、版本历史（N 个版本）、部署记录；未配置发布流程时显示"未配置"。

### 4.7 用户与权限 `/apps/[id]/access`
- 分区：角色与策略、组织授权、团队身份、Application identity、应用角色、应用准入、策略模拟。
- 用户列表筛选：成员状态 / 登录来源 / 团队身份 / 应用角色 / 应用准入。
- 用户类型覆盖：应用用户、企业微信用户、微信小程序用户；状态：正常/停用、已准入/未准入。

### 4.8 应用配置 `/apps/[id]/settings`
- 分组：应用管理、开发与变更、能力配置、权限与安全、外观与资源。

### 4.9 团队设置 `/settings/team?tab=members`
- 团队信息：团队名称、头像上传、保存修改。
- 成员：列（用户/团队角色/状态/操作）；角色五档：所有者/管理员/成员/只读/应用用户；操作：暂停/移除。
- 邀请成员弹窗：邮箱 + 团队角色。
- 另有内部子 Tab：组织架构、企业微信、微信小程序（"管理团队成员，并查看通过微信小程序进入应用的外部用户"）。

### 4.10 团队 Skills `?tab=skills`
- 列表空态"尚无团队 Skill"；「新建 Skill」表单：
  - 名称（占位 `customer-research`，小写 kebab-case）
  - 状态（已启用/已停用）
  - 描述（"说明适用场景，Agent 会据此判断何时使用"）
  - Skill 文件树：SKILL.md 入口 + scripts/references/assets 子目录 + 上传资产文件
  - SKILL.md 内容编辑区；保存版本按钮

### 4.11 团队 MCP `?tab=mcp`
- 列表空态"尚未配置团队 MCP"；「添加 MCP」表单：
  - 稳定标识（占位 `github-tools`，小写 kebab-case）
  - 状态（已启用/已停用）、名称（"GitHub 工具"）、说明（"查询仓库、Issue 和 Pull Request"）
  - Streamable HTTP Endpoint（占位 `https://mcp.example.com/mcp`）
  - 请求头（可添加多条）、「测试并读取工具」按钮、保存配置

### 4.12 智能能力 `?tab=capabilities`
- 新建 Profile；运行时 Profile 下拉（团队默认）。
- 表格列：Profile / 文字模型 / 视觉模型 / 语音模型 / 密钥 / 操作（编辑/删除）。
- 团队能力额度与用量统计。

### 4.13 模型配置 `?tab=ai-profiles`
- 新建 Profile；Agent 下拉（选择 Agent 运行时）。
- 表格列：Profile / Agent endpoint / Agent 模型 / 操作（编辑/删除）。

## 5. Agent Server API 全量清单（来自公开 OpenAPI）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/chatkit` | POST | **ChatKit 协议单端点**：流式操作返回 SSE（text/event-stream），非流式返回 JSON |
| `/chatkit/runs` | POST | 创建后台 Run（202） |
| `/chatkit/runs/{run_id}/snapshot` | GET | 后台 Run 快照 |
| `/chatkit/runs/{run_id}/events` | GET | SSE 订阅 Run 事件（`after`/`eventIndex` 断点续传） |
| `/chatkit/runs/{run_id}/cancel` | POST | 取消 Run |
| `/chatkit/runs/{run_id}/resolve` | POST | 人工介入决策：`resolution ∈ {retry, skip, end}` |
| `/chatkit/attachments` | POST | 附件上传（multipart，201） |
| `/chatkit/attachments/{id}` | DELETE | 删除附件 |
| `/chatkit/apps/{app_id}/attachments/{id}` | GET | 读取应用附件 |
| `/chatkit/threads/search` | GET | 会话搜索（`q`、`limit=50`） |
| `/chatkit/threads/{id}/pinned` | PATCH | 置顶 `{"pinned": bool}` |
| `/chatkit/threads/{id}/visibility` | PATCH | 可见性 `{"visibility": "private"\|"team"}` |
| `/chatkit/threads/{id}/active-run` | GET | 线程当前活动 Run |
| `/chatkit/threads/active-runs` | GET | 批量查询活动 Run（`thread_ids`） |
| `/chatkit/threads/{id}/task-plan` | GET | 线程任务计划 |
| `/chatkit/threads/{id}/proposal` | GET | **获取最近一次 SpecPatch 提案**（ChatKit 事件协议之外，流结束后客户端单独拉取；服务重启后回退到持久化线程元数据） |
| `/chatkit/apply` | POST | **用户确认后应用补丁** `{"app_id", "thread_id"}` |
| `/chatkit/apps/{app_id}/runs/{run_id}/browser-frame` | GET | **实时浏览器帧**（Agent 运行中应用的 live 预览） |
| `/internal/mcp/discover` | POST | MCP 服务发现 `{"endpointUrl", "headers"}` |

**核心工作流还原**：用户在 Builder 对话 → `/chatkit` SSE 流式返回（含工具调用、任务计划）→ Agent 产出 **SpecPatch 提案** → 前端拉 `/proposal` 渲染 diff → 用户确认 → `POST /apply` 落库为新 AppSpec 版本 → Builder 刷新。

## 6. AppSpec v0.3 数据格式（实测样本解析）

平台的核心抽象：整个应用是一份声明式 JSON Spec，版本化存储（`specver_<uuid>`），draft/published 双指针。

顶层 15 个键：

```jsonc
{
  "specVersion": "0.3",
  "app":       { "id", "name", "description", "metadata": {"tenantId","createdBy","createdAt","updatedAt"} },
  "models":    [ /* 数据模型（Airtable 风格） */ ],
  "seeds":     [],
  "pages":     [ /* 页面定义 */ ],
  "actions":   [ /* 动作 */ ],
  "policy":    { "roleDefinitions", "attributeDefinitions", "rules", "publicAccess" },
  "identityProfiles": [],
  "integrations": [],
  "workflows": [],
  "sharedResources": [],
  "sharedBindings": [],
  "navigation": { "items": [] },
  "shell":     { "mode": "..." },
  "runtimeCapabilities": { "ai", "speech", "documents" }
}
```

model/field 示例（来自真实应用"企业IT系统架构图"）：

```jsonc
{
  "id": "vendor_catalog", "name": "供应商目录",
  "fields": [
    {"id":"name","name":"供应商名称","type":"text","required":true,"validation":{},"display":{}},
    {"id":"system_types","name":"覆盖系统类型","type":"relation","required":false,
     "validation":{},"display":{},
     "relation":{"targetModelId":"system_catalog","cardinality":"many","displayFieldId":"name"}},
    {"id":"category","name":"系统分类","type":"select","required":true,
     "options":["核心业务","生产制造","供应链物流","协同办公","客户与营销","数据与平台","基础设施与安全"]}
  ],
  "relationships": [], "views": [], "importMappings": [], "indexes": []
}
```

字段类型已观测到：`text`、`select`（带 options）、`relation`（带 targetModelId/cardinality one|many/displayFieldId）。

## 7. 平台 API 已验证端点

| 端点 | 说明 |
|---|---|
| `POST /api/auth/login` | 入参 `{email, password}`；返回 `{user, tenant, membership, tenants[], authContext}` 并种 `air_session`/`air_csrf` |
| `GET /api/auth/me` | 未登录 401 `AUTHENTICATION_REQUIRED` |
| `GET /api/tenants` | 租户 |
| `GET /api/apps` | 应用列表：`{id(app_uuid或短slug), tenantId, name, description, iconAssetId, status: draft\|active, currentDraftSpecVersionId, currentPublishedVersionId, createdAt, updatedAt}` |
| `GET /api/apps/{id}/spec` | 完整 AppSpec（含 specVersion） |
| `GET /api/apps/{id}/product-memory` | 产品记忆（浏览器流量观测） |
| `GET /api/apps/{id}/audit-events` | 审计事件（同上） |
| `GET /api/apps/{id}/workspace`、`/environments` | 工作区/环境（同上） |

ID 体系：`user_<uuid>`、`tenant_<uuid>`、`app_<uuid>`（另有 `crm`/`it` 等短 slug）、`specver_<uuid>`、`asset_<uuid>`、`req_<uuid>`。

实测租户信息：`membership.role = admin`，`authContext.subjectType = platform_user`。

## 8. 排除 Pi / DSH 的论证

| 维度 | Pi 1.3.0 | DSH 0.2.1-rc.2 | 目标平台 |
|---|---|---|---|
| 形态 | CLI/RPC/TS SDK 的 coding agent harness（`@earendil-works/pi-*`） | Cordis 插件化 agent harness（`npx @deepseek-ai/dsh web`，端口 3080） | 多租户 SaaS Web 平台 |
| 前端 | TUI（无 Web UI） | Vite 构建的 shell library | Next.js App Router |
| 会话/API | 本地 AUTH_FILE/OAuth | 本地会话 | Express `air_session` + FastAPI cookie |
| 关键词命中 | 无 `chatkit`/`AppSpec`/`product-memory` | 无 `chatkit`/`FastAPI`/`AppSpec` | 全部命中 |
| 多租户 | 无 | 无 | tenants/apps 双层 |

结论：两者均无匹配指纹，**排除**。Pi/DSH 属于"编码 Agent harness"品类，与目标平台"AI 低代码应用搭建平台"是不同物种。

## 9. 与开源生态的关系

平台自研部分：Next.js 前端、Express 平台 API、AppSpec 规范本身。
平台开源依赖（可复用）：

| 组件 | 来源 | 许可证 | 用途 |
|---|---|---|---|
| `openai-chatkit`（PyPI） | openai/chatkit-python | Apache-2.0 | Agent Server 的 ChatKit 协议实现（`ChatKitServer` + FastAPI 单端点 + SSE） |
| `@openai/chatkit-react` / chatkit-js | openai/chatkit-js | Apache-2.0 | 前端对话组件（`useChatKit({api:{url, domainKey}})`） |

其 Agent Server 的端点布局（单 `/chatkit` + threads/runs/attachments 扩展）与 `openai-chatkit` 的标准形态高度吻合，**该服务几乎可以确定是基于 openai-chatkit SDK 二次开发的**。
